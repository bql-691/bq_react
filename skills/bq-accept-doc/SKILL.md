# 接受一篇文档

先读 `rules/bq-doc-driven.md` 和 `skills/bq-write-doc/SKILL.md` 中该种类的章节。用户请求里没有写出文档路径时，列出 `doc/项目文档/功能模块/` 与 `doc/项目文档/基础应用/` 下的文档路径，然后停止。不写代码。

当前对话里还没有同时出现「文档没有问题」和「业务正常」时，列出文档路径并停止。不写代码。请用户确认，或在文档需要修改时回复「更新文档」。

要同时接受另一篇正式文档或另一个 `src/features/<目录>` 时，用户回复里还要有「允许跨模块」和这些路径。没有写出的路径不接受。

## 一条业务

对照用户请求里写出路径的业务文档和该模块主文档。下面任何一项缺失就列出缺口并停止：

- 业务定义。
- 时序图。参与者和箭头使用类名、方法名。
- 时序里的类在主文档中有定义。
- 时序里的方法在主文档中有签名。
- 时序图中的方法会改变聚合根上的数据，且模块主文档的核心模型没有写不变条件。
- 时序或主文档出现页面，且两篇文档都没有写登录策略。登录策略只写这三种之一：公开、需登录、仅访客。

## 一个基础应用

对照用户请求里写出路径的那一篇基础应用文档。下面任何一项缺失就列出缺口并停止：

- 功能定义。
- 对外入口：类或函数、文件路径、各自负责的事。
- 文档中没有时序图，也没有带文件路径的使用示例。

缺口按「缺什么、文档路径、要补的章节」写出，并询问：「是否更新文档？」用户回复「更新文档」后，改用 `skills/bq-write-doc/SKILL.md`。用户回复「不更新文档」后，停止。不编写文档里没有的行为。
